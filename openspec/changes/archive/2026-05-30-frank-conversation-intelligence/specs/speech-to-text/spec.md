# 语音转文字（Speech-to-Text）能力规格

## 概述

本文档定义了 Frank Phase 3 中语音转文字（STT）能力的详细需求与验收场景。STT 模块负责将麦克风采集的音频实时转换为中文文本，作为对话式 AI 交互的语音输入通道。核心引擎基于 `faster-whisper` 中型模型（medium），在本地 CPU 上运行推理，无需云端依赖。

---

## 新增需求

### 需求 1：faster-whisper medium 模型加载

**描述**：应用启动时异步加载 faster-whisper medium 模型。模型文件缓存于 `data/models/` 目录下。加载成功后方可进行 STT 转录；加载失败时应优雅降级至降级模式，不阻塞应用主流程。

**验收标准**：

1. 模型加载为异步操作，不阻塞 Electron 主进程或渲染进程启动。
2. 模型文件优先从 `data/models/` 本地缓存读取；若缓存不存在，自动下载并缓存至该目录。
3. 加载结果（成功/失败）通过内部状态事件上报，供 UI 层展示 STT 就绪状态。
4. 加载失败时，系统进入降级模式：隐藏语音输入按钮，禁用 STT 相关功能，并提示用户检查模型文件或网络。
5. 降级模式下，应用的文本聊天等非 STT 功能完全不受影响。

#### 场景：正常加载流程

**给定** 应用首次启动且网络可用  
**当** 应用初始化进入 `Boot` 状态  
**则** 系统异步初始化 `WhisperModel(model_size="medium", device="cpu", compute_type="int8")`  
**并且** 模型文件下载/加载进度通过 `stt.model_loading_progress` 事件推送  
**并且** 加载完成后，STT 状态标记为 `ready`  

#### 场景：已缓存模型快速加载

**给定** `data/models/` 下已存在 medium 模型文件  
**当** 应用启动  
**则** 跳过下载，直接从磁盘加载模型  
**并且** 加载时间应在 3 秒内完成（基于 CPU 环境）  

#### 场景：加载失败进入降级模式

**给定** 模型文件损坏或网络不可用  
**当** 模型加载抛出异常（如 `OSError`, `ValueError`）  
**则** 系统捕获异常，设置 STT 状态为 `degraded`  
**并且** 向 Electron 发送 `stt.status_changed` 事件，状态为 `degraded`  
**并且** 语音输入按钮在 UI 中隐藏/禁用  
**并且** 文本聊天输入框显示小字提示："语音输入暂不可用"

### 需求 2：从环形缓冲区提取音频片段

**描述**：当唤醒词命中时，从环形缓冲区（ring buffer）中提取从唤醒词触发点前 1.5 秒开始、到检测到静默结束的音频段。若采样率或声道数与模型要求不匹配，自动重采样至 16kHz 单声道。

**验收标准**：

1. 环形缓冲区维护最近 N 秒的 PCM 音频数据。
2. 唤醒词命中时，获取触发时间戳 `trigger_ts`。
3. 起始位置为 `trigger_ts - 1.5s`，结束位置为 `trigger_ts + 持续说话至静默检测`。
4. 提取的音频片段若采样率 ≠ 16000 或声道数 ≠ 1，须进行重采样。
5. 最终输出为 16kHz、16-bit、单声道 PCM 数据，可直接送入 faster-whisper。

#### 场景：唤醒后提取完整语音段

**给定** 环形缓冲区持续缓存 10 秒音频，唤醒词在 `T=5.0s` 命中  
**当** 唤醒词检测回调被触发  
**则** 系统计算起始位置 `T=3.5s`（5.0 - 1.5）  
**并且** 持续从缓冲区读取音频直至 VAD 检测到静默（假设在 `T=8.2s`）  
**并且** 提取 `[3.5s, 8.2s]` 共 4.7 秒的音频段  
**并且** 输出为 16kHz 单声道 PCM，长度 75200 样本（4700ms × 16）  

#### 场景：自动重采样至 16kHz 单声道

**给定** 系统麦克风采集音频为 44.1kHz 立体声  
**当** 提取音频片段后  
**则** 使用 `soundfile` 或 `librosa` 将 44.1kHz 立体声重采样为 16kHz 单声道  
**并且** 重采样后的数据确保波形不失真（通过峰值归一化验证）  

---

### 需求 3：STT 转录

**描述**：将提取的音频片段送入 faster-whisper 模型进行语音转文字，语言设置为中文（`language=zh`），束搜索宽度 `beam_size=5`。输出包含转录文本和置信度分数。

**验收标准**：

1. 调用 `model.transcribe(audio, language="zh", beam_size=5)`。
2. 若语言自动检测显示非中文概率 > 0.3，发出 `stt.language_mismatch` 警告事件。
3. 返回结构包含：`{ text: str, confidence: float }`。
4. 置信度取所有片段置信度的均值。
5. 空音频（纯静音）返回 `{ text: null, confidence: 0.0 }`，不进行转录。

#### 场景：成功转录中文语音

**给定** 已加载 faster-whisper medium 模型  
**当** 16kHz 单声道音频片段送入 `transcribe()`  
**则** 返回 `{ text: "今天天气怎么样", confidence: 0.92 }`  
**并且** 文本为简体中文，无标点符号省略（保留模型输出的自然标点）  

#### 场景：空音频跳过转录

**给定** 提取的音频段为纯静音（最大振幅 < 阈值 -50dBFS）  
**当** 调用 `transcribe()` 前检测  
**则** 跳过模型推理  
**并且** 返回 `{ text: null, confidence: 0.0, skipped: true }`  
**并且** 不产生 `stt.transcription` 事件  

---

### 需求 4：STT 事件推送

**描述**：转录完成后，通过 IPC 向 Electron 推送 `stt.transcription` 事件，包含文本、置信度、音频时长（毫秒）和检测语言。

**验收标准**：

1. 事件名称为 `stt.transcription`。
2. 事件载荷格式为：
   ```json
   {
     "text": "今天天气怎么样",
     "confidence": 0.92,
     "duration_ms": 3200,
     "language": "zh"
   }
   ```
3. 事件在主进程和渲染进程均可接收。
4. 推送时机：转录完成后立即推送，不缓冲、不合并。
5. 推送失败（如渲染进程未就绪）应记录日志但不影响转录流程。

#### 场景：转录后事件推送

**给定** 音频片段转录完成，输出文本 "打开日历"  
**当** 转录回调被调用  
**则** 构造事件载荷 `{ text: "打开日历", confidence: 0.88, duration_ms: 1500, language: "zh" }`  
**并且** 通过 `ipcMain.emit("stt.transcription", payload)` 发送至 Electron 主进程  
**并且** 渲染进程通过 `ipcRenderer.on("stt.transcription", handler)` 接收并展示  

#### 场景：推送失败降级

**给定** 渲染进程尚未完成初始化  
**当** `ipcMain.emit` 调用时无监听者  
**则** 记录警告日志 `[STT] No listeners for stt.transcription, event dropped`  
**并且** 转录结果在内存中保留 5 秒供后续消费，超时后丢弃  

---

### 需求 5：对话状态下的持续监听

**描述**：用户通过唤醒词触发首次转录后，麦克风保持开启状态，用户可直接连续说话而无需再次唤醒。VAD（语音活动检测）在检测到语音结束时自动触发下一次转录。

**验收标准**：

1. 首次唤醒 + 转录完成后，系统进入 "持续监听" 子状态（`Chat.speech_continuous`）。
2. 持续监听期间，环形缓冲区继续采集音频，VAD 持续运行。
3. VAD 检测到语音开始 → 开始记录语音段。
4. VAD 检测到语音结束（静默持续 ≥ 800ms）→ 自动触发转录。
5. 持续监听超时（默认 15 秒无语音）→ 自动关闭麦克风，退回普通文本模式。
6. 用户可通过手动按钮或说"结束"（需后续 NLU 支持）退出持续监听。

#### 场景：唤醒后连续对话

**给定** 唤醒词命中且首次转录完成，系统处于 `Chat.speech_continuous` 状态  
**当** 用户说 "打开日历"（转录完成）  
**并且** 紧接着说 "查看明天的日程"（间隔 1.2 秒）  
**则** "查看明天的日程" 的音频被 VAD 检测为新的语音段  
**并且** 静默 800ms 后自动转录，无需唤醒词  
**并且** 推送第二条 `stt.transcription` 事件  

#### 场景：持续监听超时自动关闭

**给定** 系统处于 `Chat.speech_continuous` 状态  
**当** 连续 15 秒内无 VAD 检测到语音活动  
**则** 系统发出 `stt.listening_timeout` 事件  
**并且** 状态退出至 `Chat.idle`（纯文本模式）  
**并且** 麦克风资源释放  
**并且** UI 上语音指示灯熄灭，输入框恢复文本输入焦点  

#### 场景：手动退出持续监听

**给定** 用户处于对话中，系统处于 `Chat.speech_continuous`  
**当** 用户点击 UI 上的 "停止语音" 按钮  
**则** 立即停止麦克风采集  
**并且** 丢弃当前未完成的音频片段  
**并且** 状态退回 `Chat.idle`

### 需求 6：性能要求——CPU 推理实时率 < 1.0

**描述**：所有 STT 转录推理在 CPU 上进行，不得依赖 GPU。转录耗时必须小于音频实际时长（即实时率 < 1.0），确保用户体验无延迟堆积。

**验收标准**：

1. 推理设备固定为 `device="cpu"`，使用 `compute_type="int8"` 以优化 CPU 性能。
2. 实时率（RTF）= 转录耗时 / 音频时长，RTF 须 < 1.0。
3. 对 5 秒以内短句，RTF 目标 < 0.5（即 5 秒音频在 2.5 秒内完成转录）。
4. 性能测试在目标 CPU（如 Intel i5-12400 或同等）上验证。
5. 透传 `faster-whisper` 的 `num_workers` 参数以利用多核并行。

#### 场景：短句实时率达标

**给定** 系统运行于 Intel i5-12400 CPU，4 核参与推理  
**当** 输入音频时长为 3.2 秒（16kHz，51200 样本）  
**则** 调用 `model.transcribe()` 耗时应在 1.0 ~ 2.5 秒范围内  
**并且** 计算 RTF = 1.8 / 3.2 ≈ 0.56，满足 < 1.0 要求  

#### 场景：长句推理不堆积

**给定** 用户连续说出 30 秒的长语音段  
**当** 转录完成后  
**则** 转录总耗时应在 20 ~ 28 秒之间（RTF < 1.0）  
**并且** 不阻塞后续音频片段的 VAD 检测和采集  
**并且** 转录期间的内存增长不超过 200MB

## 附录：数据流示意

```
麦克风 → 环形缓冲区 ──┬──→ VAD 检测
                      │        │
                      │  唤醒词命中 ─→ 音频截取 [trigger-1.5s, trigger+until_silence]
                      │        │
                      │    重采样至 16kHz 单声道
                      │        │
                      │    faster-whisper transcribe(language=zh, beam_size=5)
                      │        │
                      │    { text, confidence, duration_ms, language }
                      │        │
                      │    IPC → stt.transcription → Electron UI
                      │
                      └──→ 持续监听（Chat.speech_continuous）
                             │
                         VAD 静默 ≥ 800ms → 自动转录
                             │
                         超时 15s → 关闭麦克风
```
