# ui-shell — 桌面 UI 外壳 (Phase 3 DELTA)

## MODIFIED Requirements

### Requirement: 功能型聊天面板（原聊天面板占位）

原聊天面板为静态占位显示个性化欢迎语（Idle 隐藏 / Auth 显示 "下午好，[name] [badge]" / Chat 显示 "[name]，我在听"）。现修改为全功能型聊天界面，包含历史消息列表、自动滚动至底部行为、以及随底层子状态（sub-state）动态响应的输入状态指示。

**消息列表布局：**
- 消息列表 SHALL 占据面板主体区域，采用弹性布局（flex column），消息项从底部向上排列
- 列表容器 SHALL 启用纵向滚动（overflow-y: auto），并在新消息到达时自动滚动至底部
- 滚动至底部 SHALL 仅在用户未主动向上翻阅历史消息时自动执行；若用户已上滚查看历史，新消息到达时不抢夺滚动位置，但 SHALL 在底部显示 "[N] 条新消息" 浮窗按钮，点击后平滑滚动至底部
- 消息列表背景 SHALL 为半透明毛玻璃效果（backdrop-filter: blur），与窗口整体风格一致

**输入状态指示区域：**
- 消息列表底部 SHALL 固定显示输入状态指示区域，反映底层状态机的当前子状态（sub-state）
- 各子状态文字提示如下：
  - Listening → "正在听..." + 波形动画
  - Transcribing → "正在转录..." + 脉冲圆点动画
  - Thinking → "正在思考..." + 旋转加载动画
  - Speaking → "正在说话..." + 音量条动画
- 当系统处于 Idle/Standby 状态时，输入状态区域 SHALL 显示 "点击或按空格开始对话"
- 该指示区域 SHALL 与子状态动画（见 ADDED: 子状态动画）视觉联动

**会话历史加载：**
- 应用启动时，SHALL 从本地存储中加载最近一次会话的消息记录
- 默认加载最近 50 条消息，并提供 "加载更早消息" 按钮（位于消息列表顶部），点击后每次追加加载 30 条
- 消息记录 SHALL 使用 SQLite 本地存储，表结构包含：消息 ID（UUID）、角色（user/assistant）、内容文本、时间戳、关联的 TTS 音频文件路径（可选）

#### Scenario: 用户新消息自动滚动至底部

- **WHEN** 用户说话完毕，转录文本生成一条新的用户消息气泡
- **THEN** 消息列表自动滚动至底部，展示最新消息

#### Scenario: 用户翻阅历史时不抢夺滚动

- **WHEN** 用户已向上滚动消息列表查看历史消息
- **AND** 新消息到达
- **THEN** 消息列表不自动滚动，底部显示 "[N] 条新消息" 浮窗按钮

#### Scenario: 启动时加载最近会话

- **WHEN** 应用启动且本地存储中存在历史会话记录
- **THEN** 消息列表加载最近 50 条消息并展示，自动滚动至底部

#### Scenario: 转录中显示输入状态

- **WHEN** 底层状态机子状态切换至 Transcribing
- **THEN** 输入状态指示区域显示 "正在转录..." 及脉冲圆点动画，输入框区域不可交互

## ADDED Requirements

### Requirement: 对话消息气泡

系统 SHALL 在聊天面板中渲染对话消息气泡（Message Bubble），以区分用户语音输入和助手的 LLM 回复。消息气泡 SHALL 以时间顺序纵向排列。

**用户消息气泡（User Bubble）：**
- 右对齐显示，背景色为蓝色渐变（#2196F3 → #1976D2）
- 文本颜色白色，字号 14px，行高 1.5
- 气泡形状：右上角直角、其余三角圆角（tail 朝右），圆角半径 12px
- 气泡内边距：上下 10px、左右 14px
- 气泡最大宽度为面板宽度的 75%
- 气泡上方 SHALL 显示时间戳（格式 "HH:mm"，灰色 12px）
- 气泡内文本为 ASR 系统转录后的用户语音文本
- 气泡下方不显示任何操作按钮

**助手消息气泡（Assistant Bubble）：**
- 左对齐显示，背景色为灰色（#2D2D2D）或深色主题色
- 文本颜色浅色（#E0E0E0），字号 14px，行高 1.6
- 气泡形状：左上角直角、其余三角圆角（tail 朝左），圆角半径 12px
- 气泡内边距：上下 12px、左右 16px
- 气泡最大宽度为面板宽度的 85%（比用户气泡略宽，容纳更长文本）
- 气泡上方 SHALL 显示 "Frank" 标签和发布时间戳
- 气泡底部 SHALL 包含 TTS 播放控制按钮组（见 ADDED: TTS 控制）
- 当助手消息为流式输出（streaming）时，气泡 SHALL 显示打字机效果，逐字展现文本

**空状态：**
- 当消息列表为空且无历史会话时，SHALL 显示空状态引导文案 "开始对话吧 — 点击麦克风或按空格键说话"

**消息分组：**
- 同一角色连续多条消息 SHALL 合并显示，仅首条消息显示头像/标签和时间戳，后续连续消息气泡间间距缩小至 4px
- 用户与助手交替时，气泡间距为 12px

#### Scenario: 用户语音转录后显示右对齐气泡

- **WHEN** ASR 系统完成转录并生成用户消息文本 "今天天气怎么样？"
- **THEN** 聊天面板中出现右对齐蓝色气泡，内容为 "今天天气怎么样？"，上方显示当前时间戳，无操作按钮

#### Scenario: 助手回复显示左对齐气泡带 TTS 按钮

- **WHEN** LLM 生成回复文本 "今天天气晴朗，气温 25°C"
- **THEN** 聊天面板中出现左对齐灰色气泡，内容为 "今天天气晴朗，气温 25°C"，上方显示 "Frank" 标签和时间戳，底部包含 TTS 播放按钮

#### Scenario: 流式输出显示打字机效果

- **WHEN** LLM 以流式方式返回回复，文本逐块到达
- **THEN** 助手气泡中文本以打字机动画逐字呈现，光标闪烁表示输出进行中

#### Scenario: 连续用户消息合并显示

- **WHEN** 用户连续发送两条消息 "你好" 和 "今天天气怎么样"（中间无助手回复）
- **THEN** 两条消息气泡右对齐排列，间距缩小至 4px，仅首条显示时间戳

#### Scenario: 空消息列表显示引导文案

- **WHEN** 首次启动且无历史会话记录
- **THEN** 消息列表中央显示 "开始对话吧 — 点击麦克风或按空格键说话"

### Requirement: 子状态动画

系统 MUST 为底层状态机的四个子状态（Listening、Transcribing、Thinking、Speaking）提供对应的视觉动画反馈。动画 SHALL 在聊天面板底部的输入状态指示区域渲染。

**Listening — 波形动画：**
- 渲染为一组垂直条形（5 条，高度不等），从左至右排列
- 条形高度在 4px 至 24px 之间随机变化
- 使用 CSS `@keyframes` 实现高度周期性脉动，各条形动画延迟不同（0s / 0.1s / 0.2s / 0.3s / 0.4s），模拟音频波形
- 条形颜色为蓝色（#2196F3），宽度 3px，间距 3px
- 动画周期 1.2s，无限循环
- 动画旁显示文字 "正在听..."

**Transcribing — 脉冲圆点动画：**
- 渲染为三个水平排列的圆点，直径 6px
- 使用 CSS `@keyframes` 实现 opacity 和 scale 的交替变化
- 圆点依次放大再缩小，视觉呈现"从左到右流动"的效果
- 圆点颜色为橙色（#FF9800）
- 动画周期 1.4s，圆点间延迟 0.2s
- 动画旁显示文字 "正在转录..."

**Thinking — 旋转加载动画：**
- 渲染为细圆环加载指示器（spinner），外径 20px，边框宽度 2px
- 圆环颜色为紫色（#9C27B0），使用 CSS `@keyframes` 实现 360 度旋转
- 动画周期 1s，线性无限旋转
- 圆环旁显示文字 "正在思考..."

**Speaking — 音量条动画：**
- 渲染为一组垂直条形（7 条），与 Listening 波形视觉对称但颜色不同
- 条形高度根据音量实时变化（通过 Web Audio API 分析音频电平）
- 颜色为绿色渐变（#4CAF50 → #81C784）
- 条形宽度 3px，间距 2px
- 无音频输出时，显示静态低电平状态（所有条形高度 4px）
- 动画旁显示文字 "正在说话..."

**动画切换规则：**
- 子状态变更时，旧动画 SHALL 立即停止，新动画 SHALL 立即启动，无过渡延迟
- 子状态变更至非四子状态（如 Idle）时，所有动画 SHALL 停止，指示区域恢复默认文字

#### Scenario: 切换到 Listening 显示波形动画

- **WHEN** 子状态从 Idle 切换至 Listening
- **THEN** 输入状态指示区域显示蓝色波形动画及文字 "正在听..."

#### Scenario: 切换到 Transcribing 显示脉冲圆点

- **WHEN** 子状态从 Listening 切换至 Transcribing
- **THEN** 波形动画立即停止，显示橙色脉冲圆点动画及文字 "正在转录..."

#### Scenario: 切换到 Thinking 显示旋转加载

- **WHEN** 子状态从 Transcribing 切换至 Thinking
- **THEN** 脉冲圆点动画立即停止，显示紫色旋转加载动画及文字 "正在思考..."

#### Scenario: 切换到 Speaking 显示音量条

- **WHEN** 子状态从 Thinking 切换至 Speaking
- **THEN** 旋转加载动画立即停止，显示绿色音量条动画及文字 "正在说话..."

#### Scenario: 返回 Idle 停止所有动画

- **WHEN** 子状态从 Speaking 切换至 Idle
- **THEN** 所有动画停止，指示区域显示 "点击或按空格开始对话"

### Requirement: TTS 控制

系统 SHALL 为每条助手消息气泡提供 TTS（文字转语音）播放控制，并提供一个全局音量设置在设置面板中。

**消息气泡内 TTS 按钮：**
- 每条助手消息气泡底部 SHALL 显示三个按钮组成的控制组，水平排列，间距 8px
- 按钮均为图标按钮，尺寸 24×24px，圆角 4px，半透明背景（hover 时变为不透明）
- 按钮列表：
  1. **播放/暂停按钮** — 默认显示 ▶ 图标；点击后开始 TTS 朗读该条消息文本，图标切换为 ⏸ 暂停；再次点击暂停朗读，图标恢复 ▶
  2. **重播按钮** — 显示 ↺ 图标；点击后停止当前朗读并从开头重新播放
  3. **朗读状态指示** — 当该消息正在 TTS 朗读时，按钮组左侧或下方 SHALL 显示一个绿色小圆点或进度条（可选波浪动画）
- 同一时刻最多只能有一条消息正在 TTS 朗读。当用户点击另一消息的播放按钮时，SHALL 自动停止当前朗读，切换至新消息
- 播放完成后，播放按钮恢复 ▶ 图标，朗读状态指示消失

**音量滑块（设置面板内）：**
- 在设置面板中新增 "语音输出" 区域，包含：
  - **音量滑块**：范围 0–100，默认值 80
  - **语速选择**：下拉选择器，选项为 "慢速（0.8x）" / "正常（1.0x）" / "快速（1.2x）"，默认 "正常"
  - **语音引擎选择**：下拉选择器，列出可用 TTS 引擎（如 "System（本地）"、"Edge Online"），根据后端能力动态加载
- 音量滑块 SHALL 实时生效，无需重启
- 音量设置 SHALL 持久化至本地配置文件

**TTS 状态同步：**
- 渲染进程 SHALL 通过 IPC 与主进程同步 TTS 播放状态，包括：当前播放消息 ID、播放进度（百分比）、播放状态（playing / paused / stopped）
- 主进程 SHALL 将 TTS 状态转发至 Python 后端，确保 Speak 子状态与 TTS 播放同步

#### Scenario: 点击播放按钮朗读助手消息

- **WHEN** 用户点击某条助手消息的 ▶ 播放按钮
- **THEN** 按钮切换为 ⏸ 暂停图标，TTS 引擎开始朗读该消息文本，朗读状态指示绿点亮起

#### Scenario: 播放中切换到另一消息

- **WHEN** 消息 A 正在 TTS 朗读中，用户点击消息 B 的播放按钮
- **THEN** 消息 A 的朗读停止（按钮恢复 ▶），消息 B 开始朗读（按钮切换 ⏸）

#### Scenario: 设置音量实时生效

- **WHEN** 用户在设置面板中将音量滑块从 80 拖拽至 50
- **THEN** TTS 输出音量实时降低，无需重启或刷新

#### Scenario: 重播从头开始

- **WHEN** 消息正在 TTS 朗读中或已播放完成，用户点击 ↺ 重播按钮
- **THEN** 朗读停止（如有），从文本开头重新播放，播放按钮切换为 ⏸

#### Scenario: 播放完成恢复默认状态

- **WHEN** TTS 朗读到达文本末尾
- **THEN** 播放按钮恢复 ▶ 图标，朗读状态指示消失

### Requirement: 免唤醒命令反馈（Toast 通知）

系统 SHALL 在用户通过免唤醒命令（wake-free command）执行操作时，提供即时视觉反馈。免唤醒命令指在非对话状态下直接说出预设指令（如 "显示时间"、"开启节电模式"），系统执行后不进入 Chat 状态、不生成消息气泡。

**Toast 通知样式：**
- 渲染为小型浮动通知条，位于主内容区域底部中央，距离底部 60px
- 背景色为半透明深色（rgba(0, 0, 0, 0.8)），毛玻璃效果（backdrop-filter: blur）
- 文本颜色白色，字号 13px，内边距 8px 16px
- 圆角 8px
- 最大宽度 280px，文本超出自动换行

**显示逻辑：**
- Toast 内容为命令执行结果的简短描述，例如 "显示时间" → 显示当前时间；"开启节电模式" → 显示 "节电模式已开启"
- Toast 显示时长 2.5 秒后自动淡出（fade-out 动画，持续 0.3s）
- 若在 Toast 显示期间有新的免唤醒命令被执行，旧 Toast SHALL 立即关闭，新 Toast 重新计时显示
- Toast SHALL 可被用户点击提前关闭

**与消息气泡的关系：**
- 免唤醒命令不产生对话消息气泡，也不进入 Chat 状态
- Toast 是免唤醒命令唯一的 UI 反馈形式
- 免唤醒命令执行完毕后，系统保持原有状态不变（通常为 Idle 或 Auth）

#### Scenario: 免唤醒命令显示 Toast

- **WHEN** 用户在 Idle 状态下说出 "显示时间"
- **THEN** 系统识别为免唤醒命令，执行操作，底部弹出 Toast "现在时间：14:30"，2.5 秒后自动消失，不产生消息气泡

#### Scenario: 连续免唤醒命令重置 Toast 计时

- **WHEN** "开启节电模式" 的 Toast 显示 1 秒后，用户又说出 "显示时间"
- **THEN** 前一条 Toast 立即关闭，新 Toast "现在时间：14:30" 重新开始 2.5 秒计时

#### Scenario: 免唤醒命令不生成消息气泡

- **WHEN** 用户执行免唤醒命令 "增大音量"
- **THEN** 仅显示 Toast "音量已增大"，聊天面板中不新增任何消息气泡，系统状态保持不变

#### Scenario: 点击 Toast 提前关闭

- **WHEN** Toast 正处于显示中，用户点击 Toast 区域
- **THEN** Toast 立即消失，不等待 2.5 秒超时
