# 免唤醒命令 (Wake-Free Commands)

## 概述

免唤醒命令允许用户在无需先说唤醒词（如"弗兰克"）的情况下，直接通过语音指令触发设备的特定操作。该功能旨在提升高频、低复杂度交互场景的使用效率，同时通过多重防护机制防止误触发。

---

## ADDED Requirements

### RQ-WFC-01: 免唤醒命令白名单

定义预配置的免唤醒命令条目，每条包含关键字、动作和触发条件三个核心属性。

- **关键字 (keyword)**：触发该命令的语音文本匹配模式，支持精确短语匹配。示例：`"几点了"`、`"暂停"`、`"继续"`、`"下一首"`、`"大声点"`、`"小声点"`、`"打开灯"`。
- **动作 (action)**：匹配成功后执行的具体操作，详见 RQ-WFC-03。
- **条件 (condition)**：限制命令生效的运行时环境条件。支持以下取值：
  - `"always"` —— 不依赖任何附加条件，在任何环境下均可触发。适用于通用查询类命令，如 `"几点了"`。
  - `"media_playing"` —— 仅在媒体播放器处于活跃播放状态时触发。适用于播放控制类命令，如 `"暂停"`、`"继续"`、`"下一首"`。
  - `"tts_speaking"` —— 仅在设备正在进行 TTS（文本转语音）播报时触发。适用于音量调节类命令，如 `"大声点"`、`"小声点"`。
- 白名单以配置文件形式存储，支持运行时重载。

### RQ-WFC-02: Aho-Corasick 多模式匹配引擎

采用 Aho-Corasick 算法编译白名单关键字集合，实现 O(n) 时间复杂度的多模式字符串匹配。

- 在系统启动时或白名单变更时，将所有关键字编译为一个确定性有限自动机（trie + fail 指针）。
- 对语音转写文本进行实时匹配，在一次扫描中检测所有命中的关键字。
- **性能要求**：单次匹配延迟 < 5ms（在 500 字节以内的语音转写文本上，含 100 条以内关键字的白名单）。
- 匹配结果返回所有命中的关键字列表，供后续条件检查和动作调度使用。
- 支持中文 UTF-8 文本的高效匹配，正确处理多字节字符边界。

### RQ-WFC-03: 命令执行与动作系统

匹配成功且条件满足后，跳过 LLM 调用链路，直接执行预定义的动作函数。缩短从语音结束到动作响应的端到端延迟。

- **动作注册表**：维护一个从动作类型到具体处理函数的映射表。预定义动作类型如下：

| 动作类型 | 处理函数 | 说明 |
|---|---|---|
| `system_time` | `system_time()` | 播报当前系统时间 |
| `media_control` | `media_control(action)` | 媒体播放控制：暂停、继续、上一首、下一首 |
| `volume_adjust` | `volume_adjust(direction)` | 音量调节：调高、调低 |
| `smart_home_toggle` | `smart_home_toggle(device)` | 智能家居设备开关（占位实现，留待 Phase 4 完善） |

- 动作执行器（Action Executor）负责任务调度：确保动作在 UI 线程中安全执行，避免阻塞匹配引擎。
- 动作执行具有幂等性保障：同一命令在短时间内重复触发不超过一次（去重窗口：300ms）。

### RQ-WFC-04: 拥有者白名单管理接口

设备拥有者可通过成员面板或配置文件对免唤醒命令白名单进行增删改查操作。

- **成员面板操作**（图形界面）：
  - 查看所有已注册的免唤醒命令及其状态。
  - 新建命令条目，填写关键字、选择动作类型、设定触发条件、设置启用开关。
  - 编辑已有条目。
  - 删除条目。
  - 启用/禁用单个条目。
- **配置文件操作**：支持通过 `config.yaml`（或等效格式）进行批量管理。格式示例：

```yaml
wake_free_commands:
  - keyword: "几点了"
    action_type: system_time
    condition: always
    enabled: true
  - keyword: "暂停"
    action_type: media_control
    action_params:
      command: pause
    condition: media_playing
    enabled: true
  - keyword: "大声点"
    action_type: volume_adjust
    action_params:
      direction: up
    condition: tts_speaking
    enabled: true
```

- 每个命令条目包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `keyword` | string | 触发关键字，支持多个关键字映射到同一动作 |
| `action_type` | enum | 动作类型，取值参见 RQ-WFC-03 |
| `action_params` | object | 动作参数，按动作类型不同而异 |
| `condition` | enum | 触发条件：`always` / `media_playing` / `tts_speaking` |
| `enabled` | boolean | 是否启用该条目 |

- 白名单变更后自动触发 Aho-Corasick 自动机的重新编译。

### RQ-WFC-05: 误触发防护——三重检查机制

为防止来自电视、背景噪音等环境声源导致的误触发，命令只有在以下三个条件**同时**满足时才会执行：

- **(a) 关键字匹配** —— 语音转写文本通过 Aho-Corasick 引擎命中白名单中的关键字。
- **(b) 条件满足** —— 当前运行时环境满足命令条目定义的 `condition`（例如 `media_playing` 要求媒体播放器确实处于播放状态）。
- **(c) 人脸检测** —— 在过去 2 秒内，设备摄像头检测到有人脸正面朝向设备（即有人正在注视设备）。

**设计理由**：三重检查机制有效防止以下典型误触发场景：
- 电视中播放的对话包含关键字（未满足人脸检测条件）。
- 用户在交谈中偶然说出关键字（未满足人脸检测条件）。
- 人从设备旁走过但未看屏幕（面部朝向不满足）。

**性能要求**：人脸检测模块需在本地运行（离线推理），单次推理延迟 < 100ms，帧率不低于 10fps。

**降级策略**：如果设备未配备摄像头或摄像头不可用，则跳过条件 (c)，仅在 (a) 和 (b) 满足时触发命令。此降级行为需在配置中显式声明。

### RQ-WFC-06: 免唤醒反馈

命令执行成功后，设备应提供即时、低侵入的反馈，确认命令已被识别并执行。

- **UI 闪光反馈**：在屏幕边缘或特定区域显示一个短暂的闪光/涟漪动画（持续时间 < 500ms），颜色与当前主题一致，不打断用户当前操作。
- **可选短促提示音**：播放一个短促的确认音效（时长 < 200ms），频率和音量应设计为柔和、不刺耳。
  - 提示音可通过配置开启/关闭，默认关闭。
- **非必要不 TTS**：免唤醒命令执行后，默认不进行 TTS 语音回复，除非动作本身需要（如 `system_time()` 播报时间）。避免在快速操作场景中产生不必要的语音干扰。
- **错误反馈**：如果命令未执行（如条件不满足或人脸检测未通过），不作任何反馈，保持静默（避免向用户暴露误触发尝试）。
