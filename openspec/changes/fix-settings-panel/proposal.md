# Proposal: 修复设置界面功能缺陷

## 背景

对设置界面进行了全链路代码审查（覆盖 HTML UI → 前端 JS → IPC 桥 → Python 后端 → YAML 持久层），发现 2 个阻断级问题和 5 个高严重性问题，导致设置界面仅能完成约 40% 的设计功能。

## 问题摘要

| # | 严重性 | 问题 | 影响 |
|---|--------|------|------|
| 1 | 🔴 BLOCKER | `llm.api_base` vs `llm.base_url` 键名不匹配 | LLM API 地址设置完全无效 |
| 2 | 🔴 BLOCKER | `loadDeviceLists()` 定义但从未调用 | 设备下拉框始终为空 |
| 3 | 🟠 HIGH | 设置表单包含后端不存在的幽灵键 (`privacy.*`, `tts.volume`) | 写入的配置无人读取 |
| 4 | 🟠 HIGH | Python/Electron 默认配置不一致 | YAML 缺失时两端行为不同 |
| 5 | 🟠 HIGH | 设置 UI 缺失 60% 配置段的编辑入口 | 大量功能无法通过 UI 配置 |
| 6 | 🟠 HIGH | LLM Provider 选择器缺失 | 无法从 UI 切换 OpenAI/Ollama |
| 7 | 🟠 HIGH | `tts.volume` 值域不一致 (UI:0-100, 后端:0.0-1.0) | 音量设置无法正常工作 |
| 8 | 🟡 MEDIUM | 无加载超时/错误处理 | 加载失败时 spinner 永久卡住 |
| 9 | 🟡 MEDIUM | 缺乏服务端值校验 | 可写入非法配置值 |
| 10 | 🟢 LOW | `onSettingsCurrent` 无条件执行 | 不必要的 DOM 操作 |
| 11 | 🟢 LOW | 缺少恢复默认/取消修改功能 | 误操作无法撤销 |

## 修复目标

1. 修复所有阻断级键名不匹配，确保设置表单可以正确读写后端配置
2. 补全设备列表加载逻辑
3. 同步前后端默认配置，消除幽灵键
4. 补全缺失配置段的 UI 编辑入口（增量：先补充最常用的 3 段）
5. 添加加载失败/超时错误处理
6. 修复 `tts.volume` 值域映射

## 不变更范围

- 配置持久层（`config.py` / `config.js`）的读写逻辑本身是正确的，不修改
- YAML 文件结构保持不变
- 面板系统架构（`PanelManager`）不修改
- 不新增配置项 — 只为已有 YAML 键补充 UI 控件
