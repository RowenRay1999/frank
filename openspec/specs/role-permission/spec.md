# 角色权限体系 (Role-Permission)

## 概述

弗兰克 Phase 2 引入角色权限体系，将用户划分为四个层级，每个层级拥有不同的操作权限、资源访问范围和命令优先级。角色系统是弗兰克多用户家庭场景的核心基础设施，贯穿身份管理、会话调度、事件系统和 UI 展示。

---

## ADDED Requirements

### Requirement: 四层角色枚举与等级定义

#### Scenario: 角色枚举与层级顺序

系统定义且仅定义四个角色层级，使用枚举或等价类型表示：

- **Owner**（所有者）—— 每个部署实例仅存在一个 Owner。Owner 是系统最高权限持有者，拥有所有管理能力和资源访问权限。
- **Adult**（成人）—— 家庭中的成年成员，可使用所有常规能力，但无权修改系统配置或管理成员。
- **Child**（儿童）—— 家庭中的儿童成员，只能使用受限的技能白名单，受到每日使用时长限制。
- **Guest**（访客）—— 临时访客，仅限基础问答，不保留任何持久化数据。

枚举定义包含显式的等级序号，用于优先级比较：

| 角色 | 等级值 | 说明 |
|------|--------|------|
| Owner | `100` | 最高权限，每个部署唯一 |
| Adult | `80` | 常规成年人权限 |
| Child | `50` | 受限权限 |
| Guest | `10` | 最低权限，临时访问 |

等级值用于命令优先级冲突解决和会话抢占判定，数值越大优先级越高。

---

### Requirement: Owner 权限

#### Scenario: 成员管理

Owner 可以执行以下成员管理操作：

- **添加成员**：向家庭中添加新用户，指定其角色（Adult / Child / Guest）。
- **移除成员**：从系统中删除现有成员及其关联数据。
- **修改角色**：更改任意成员的角色（例如将 Child 升级为 Adult，或将 Adult 降级为 Child）。
- **查看成员列表**：浏览所有已注册成员及其角色状态。

不允许 Owner 将自身角色降级为非 Owner，也不允许 Owner 移除自身——系统应阻止此类操作。

#### Scenario: 系统配置修改

Owner 可以修改弗兰克的系统级配置，包括但不限于：

- 语音唤醒词与响应设置
- 网络与设备连接配置
- 技能启用/禁用开关
- 隐私与数据保留策略
- 儿童使用时间限制（全局默认值）

#### Scenario: 全数据访问

Owner 可以访问系统中的所有数据和记录，包括：

- 所有用户的会话历史（包括私密对话）
- 共享日历与笔记（具备完全读写权限）
- 系统操作日志与审计记录
- 其他用户的个人设置（只读或可编辑视配置项而定）

#### Scenario: 最高命令优先级

Owner 发起的命令在所有场景下具有最高优先级：

- Owner 的命令可以打断任何正在处理的会话（包括 Adult 和 Child 的活跃会话）。
- 当 Owner 发言时，系统应立即暂停当前会话，优先处理 Owner 的请求。
- 命令队列中，Owner 的命令始终排在最前，不受到达时间影响。

#### Scenario: 会话打断

Owner 拥有独占的会话打断权限：

- 可以中断任何角色的正在进行的会话。
- 打断后，被中断的会话状态应被保存（如上下文），以便后续恢复。
- 被中断的会话持有者会收到明确的打断通知。

---

### Requirement: Adult 权限

#### Scenario: 全部常规技能

Adult 可以使用弗兰克提供的所有常规技能，包括但不限于：

- 日常问答与对话
- 智能家居控制
- 日历管理（查看/创建/编辑共享日历事件）
- 笔记管理（查看/创建/编辑共享笔记）
- 信息查询与联网搜索
- 文件管理（上传/下载/删除个人文件）
- 所有启用的第三方技能集成

#### Scenario: 不可管理成员与配置

Adult 无权执行以下操作：

- 添加、移除或修改任何成员的角色（包括自身）。
- 修改系统级配置（如网络、语音、隐私策略等）。
- 查看或修改其他用户的个人设置。
- 访问系统操作日志或审计记录。
- 访问 Owner 的私密数据或个人会话历史。

如果 Adult 尝试执行上述操作，系统应返回权限拒绝错误，并记录该尝试。

#### Scenario: 可被 Owner 中断

Adult 的会话可以被 Owner 随时中断：

- 当 Owner 发起新命令时，如果 Adult 正在与弗兰克交互，系统应暂停 Adult 会话，优先响应 Owner。
- 被中断后，Adult 会话上下文被保存。
- Adult 会收到通知：*"Owner 正在使用系统，您的会话已暂停。"*

---

### Requirement: Child 权限

#### Scenario: 受限技能白名单

Child 只能使用经 Owner 或 Adult 管理员（如果系统另有配置）明确的技能白名单中的技能。白名单机制包括：

- **默认白名单**：系统出厂提供了一个默认技能白名单（例如基础问答、简单计算、故事朗读等教育类技能）。
- **白名单管理**：Owner 可以通过成员管理界面为每个 Child 单独配置技能白名单。
- **白名单检查**：当 Child 发出请求时，系统首先检查该请求所涉及的技能是否在白名单中。若不在，直接拒绝。
- **拒绝反馈**：当请求被拒绝时，Child 会收到友好提示：*"这个功能暂时不可用，可以试试其他问题哦。"*

不在白名单中的技能包括但不限于：
- 家庭设备控制（灯光、门锁等）
- 支付相关操作
- 系统设置修改
- 涉及成人内容的技能
- 文件系统操作

#### Scenario: 每日使用时间限制

Child 受到每日使用时长限制：

- **时长配置**：Owner 可以为每个 Child 单独设置每日最大使用时长（单位：分钟）。
- **默认限制**：若未配置，系统使用默认值（如 120 分钟/天）。
- **计费周期**：以自然日（00:00 - 23:59）为周期，累计实际对话时间。
- **超限处理**：当 Child 达到当日限制时，系统停止响应其请求，并提示：*"今天的使用时间已经到了，明天再来找我玩吧！"*
- **Owner 豁免**：如果 Owner 在同一设备上临时授权，可以覆盖该限制（临时授权需 Owner 确认）。

#### Scenario: 不可打断更高层级用户

Child 在任何情况下都不能打断或抢占更高层级用户（Owner 和 Adult）的会话：

- 当 Owner 或 Adult 正在与弗兰克交互时，Child 的请求将被排队或延迟。
- 即使 Child 先发起请求，如果更高层级的用户随后发起命令，Child 的请求将被降级。
- 系统会告知 Child：*"请稍等，家里其他人正在使用弗兰克哦。"*

---

### Requirement: Guest 权限

#### Scenario: 基础问答

Guest 只能使用最基本的问答能力：

- 仅限常识问答、天气查询、时间日期等基本信息服务。
- 不可以使用智能家居控制、日历编辑、笔记功能、文件操作。
- 不可以使用任何第三方技能集成。
- 不可以使用个性化功能（如根据用户偏好推荐内容）。

#### Scenario: 无持久化数据存储

系统不对 Guest 存储任何持久化数据：

- 会话历史在会话结束后立即清除，不写入持久化存储。
- 不保存用户的偏好设置、个性化配置或使用习惯。
- 不创建用户画像或使用记录日志（匿名化系统日志除外，仅记录操作类型不记录用户身份）。
- 任何由 Guest 创建的内容（笔记、日历事件等）在会话结束后自动丢弃。

#### Scenario: 无家庭隐私信息访问

Guest 无法访问家庭的任何私有信息：

- 无法查看家庭成员的姓名、关系、个人信息。
- 无法查看家庭共享日历或笔记。
- 无法查看家庭设备列表或状态。
- 无法查询家庭住址、联系方式等隐私信息。

#### Scenario: 会话结束后数据丢弃

Guest 会话终止时，系统确保：

- 所有会话过程中产生的临时数据被完全清理。
- 不会在本地或云端留存 Guest 对话内容的任何副本。
- 匿名化系统审计日志中仅记录操作类型和时间戳，不记录 Guest 标识或内容。

### Requirement: 命令优先级冲突解决

#### Scenario: 跨层级优先级

当多个用户同时向弗兰克发出命令时，系统按照以下规则确定优先处理顺序：

1. **Owner 始终最高**：Owner 命令无条件排在最前，不受到达时间影响。
2. **层级优先**：其他层级之间，等级值高的层级的命令优先于等级值低的层级（Adult > Child > Guest）。
3. **打断规则**：高优先级命令可以打断正在处理的低优先级会话。

伪代码示意：

```
function resolvePriority(currentSession, newCommand):
    if newCommand.role == Owner:
        // Owner 永远可以打断
        preempt(currentSession, newCommand)
    else if newCommand.role > currentSession.role:
        // 更高层级可以打断
        preempt(currentSession, newCommand)
    else:
        // 同层或更低层级，进入等待队列
        enqueue(newCommand)
```

#### Scenario: 同层级优先顺序

同一层级的用户之间采用先到先得（FCFS）原则：

- 当 Adult A 正在与弗兰克对话时，Adult B 的请求进入等待队列。
- Adult B 的请求将在当前会话结束或暂停后得到处理。
- 同层级之间不存在互相打断权限。
- 命令队列按到达时间排序，先到达的先处理。

#### Scenario: Owner 无条件抢占

Owner 是一个特例，在任何场景下都拥有无条件抢占权：

- 即使 Owner 当前正在处理其他会话（即 Owner 自身处于多任务场景），新命令也立即切换上下文。
- 不存在任何"不可打断"的豁免场景。
- Owner 的命令不进入等待队列，总是直接抢占当前处理器。

### Requirement: 事件系统角色附着

#### Scenario: state.changed 事件携带角色

所有 `state.changed` 类型的事件负载中必须包含发起操作的用户角色信息：

```json
{
  "event": "state.changed",
  "payload": {
    "entity": "light.living_room",
    "state": "off",
    "timestamp": "2026-05-30T10:30:00Z",
    "actor": {
      "user_id": "user_01",
      "user_name": "爸爸",
      "role": "owner"
    }
  }
}
```

- `actor.role` 字段必须使用枚举定义的字符串表示（`owner` / `adult` / `child` / `guest`）。
- 所有状态变更操作都必须记录 `actor` 信息，包括角色字段。
- 没有角色信息的遗留事件视为 `guest`。

#### Scenario: UI 角色徽章展示

在用户界面中，与用户名一起显示角色徽章：

- **Owner**：显示特殊标识（如👑皇冠图标或"主人"标签），颜色醒目（如金色）。
- **Adult**：显示标准用户标识（如"成人"标签），颜色中性（如蓝色）。
- **Child**：显示儿童标识（如"儿童"标签），颜色柔和（如绿色）。
- **Guest**：显示访客标识（如"访客"标签），颜色浅淡（如灰色）。

角色徽章要求在以下界面位置展示：

- 对话消息头部（每条消息显示发送者的角色徽章 + 用户名）。
- 用户列表页（成员管理界面中每个条目显示角色徽章）。
- 系统设置页（当前用户信息区域显示角色徽章）。
- 设备控制面板（操作记录显示操作者的角色徽章）。

---

## 实现说明

1. **角色枚举**应在核心身份模块中定义，作为全局类型被所有子系统引用。
2. **权限检查**应在技能调度器层面实现，作为命令处理管线的第一个环节。
3. **命令优先级**应在会话管理器中实现，与当前活跃会话状态协同。
4. **UI 角色展示**应在前端组件层抽象为可复用的 `RoleBadge` 组件。
5. **事件角色附着**应在事件总线层面完成，确保所有事件生产者无需感知角色逻辑。
