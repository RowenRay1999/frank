## 新增需求：多输出路由

### 背景

多任务 / 多会话场景下，每个用户（主用户、副用户）需要拥有独立的音视频输出通道，确保 TTS 音频路由到正确的物理设备、界面渲染到正确的显示器，互不串扰。

### 需求列表

#### 1. 音频输出设备枚举

通过 PyAudio/pywin32 WASAPI 枚举系统中所有可用的音频输出设备。将设备列表报告给 Electron 前端，数据结构如下：

```json
[
  {
    "id": "string",        // 设备唯一标识符
    "name": "string",      // 设备友好名称
    "type": "string",      // 设备类型（例如 speakers, headphones, hdmi）
    "is_default": false    // 是否为系统默认播放设备
  }
]
```

- 枚举时机：应用启动时、设备热插拔时。
- 前端收到列表后用于用户选择或自动匹配。

#### 2. 显示设备枚举

通过 Electron `screen` API 枚举所有已连接的显示器。报告给前端，数据结构如下：

```json
[
  {
    "id": "string",        // 显示器唯一标识符
    "name": "string",      // 显示器名称
    "bounds": {            // 显示器在虚拟坐标系中的位置和尺寸
      "x": 0,
      "y": 0,
      "width": 1920,
      "height": 1080
    },
    "is_primary": false    // 是否为主显示器
  }
]
```

- 枚举时机：应用启动时、显示器连接/断开时。
- 主要用于将副用户窗口路由到非主显示器。

#### 3. 用户到输出通道的绑定

每个会话（Session）启动时，绑定到唯一的输出通道，通道包含以下两个关键属性：

- `audio_device_id` —— 音频输出设备 ID
- `display_id` —— 显示器 ID

绑定规则：

- **主用户（Primary User）**：默认绑定到系统音频默认设备 + 主显示器。
- **副用户（Secondary User）**：默认绑定到预配置的副音频设备 + 非主显示器（如第二块屏幕）。
- 若无预配置，则使用系统默认；用户可在设置中手动修改绑定。

#### 4. 并行输出隔离

主用户和副用户同时使用时，各自的输出必须严格隔离：

- **音频隔离**：主用户的 TTS 语音通过主音频设备播放，副用户的 TTS 语音通过副音频设备播放。两路音频互不干扰。
- **降级策略**：若系统中仅存在一个音频输出设备（例如只有内置扬声器），则副用户的 TTS 输出降级为纯文本提示，并在界面中推送通知告知用户 "当前系统仅检测到一个音频设备，副用户的语音输出已降级为文本模式"。
- **显示隔离**：主用户窗口渲染在主显示器，副用户窗口渲染在副显示器。

#### 5. 会话结束时的通道释放

当用户离开会话（Session End）时，系统自动释放该用户绑定的输出通道：

- 音频设备标记为可用。
- 显示器标记为可用。
- 释放后的通道可被下一个进入会话的用户重新绑定使用。

实现要点：

- 通道管理模块维护一个 `Map<sessionId, Channel>`，在会话开始/结束时原子化地分配/回收通道。
- 回收时需清理所有与该通道关联的后台资源（音频流、窗口句柄等）。
