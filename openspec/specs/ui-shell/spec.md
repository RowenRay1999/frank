# ui-shell — 桌面 UI 外壳

## ADDED Requirements

### Requirement: 窗口管理

系统 SHALL 在 Electron 渲染进程中创建一个无边框浮动窗口，默认以紧凑模式（compact mode）启动，尺寸为 360×500px。窗口 SHALL 支持自定义标题栏实现拖动。系统 MUST 提供"总在最前"（always-on-top）切换按钮。窗口 MUST 支持通过拖拽边缘进行缩放，最小尺寸 300×400px，最大尺寸 1200×900px。窗口位置 SHALL 在会话间持久化（使用 electron-store 或配置文件存储）。系统 MUST 提供一个展开按钮，点击后切换至完整模式（full mode，800×600px），并在展开模式下显示侧边栏区域。

#### Scenario: 默认启动尺寸为紧凑模式
- **WHEN** 用户首次启动 Frank
- **THEN** 窗口以紧凑模式呈现，尺寸为 360×500px，显示自定义标题栏和主内容区域

#### Scenario: 拖拽边缘调整窗口尺寸
- **WHEN** 用户拖拽窗口任意边缘或角落
- **THEN** 窗口跟随鼠标缩放，且尺寸被限制在最小 300×400px 至最大 1200×900px 之间

#### Scenario: 展开按钮切换全模式
- **WHEN** 用户点击标题栏上的展开按钮
- **THEN** 窗口切换至全模式（800×600px），侧边栏区域可见

#### Scenario: 再次点击展开按钮恢复紧凑模式
- **WHEN** 用户在全模式下再次点击展开按钮
- **THEN** 窗口恢复至紧凑模式（360×500px），侧边栏隐藏

#### Scenario: 窗口位置被持久化
- **WHEN** 用户调整窗口位置后关闭并重新启动 Frank
- **THEN** 窗口恢复至上次关闭时的屏幕位置

### Requirement: 自定义标题栏

原标题栏状态标签为固定格式 "Frank - {status}"。现修改为：当系统已识别用户身份时，标题栏文本 SHALL 显示 "Frank - [display_name]"，其中 [display_name] 为已识别用户的显示名称。当身份未知或未识别时，标题栏 SHALL 保持原有格式 "Frank - {status}"。

| 场景 | 原标题栏文本 | 新标题栏文本 |
|---|---|---|
| Idle + 身份未知 | Frank - 待机中 | Frank - 待机中 |
| Idle + 已识别 | Frank - 待机中 | Frank - 小王 |
| Auth + 已识别 | Frank - 就绪 | Frank - 小王 |
| Chat + 已识别 | Frank - 对话中 | Frank - 小王 |

#### Scenario: 已识别用户显示 display_name
- **WHEN** 系统处于 Auth 状态且已成功识别用户身份（用户 display_name 为"小王"）
- **THEN** 标题栏文本显示 "Frank - 小王"，而非原生 "Frank - 就绪"

#### Scenario: 未识别用户保持默认
- **WHEN** 系统处于 Idle 状态且未有已识别用户
- **THEN** 标题栏文本显示 "Frank - 待机中"，与原有行为一致

### Requirement: 状态指示器

系统 MUST 在标题栏左侧显示一个彩色圆点作为状态指示器，反映底层状态机的当前状态。各状态对应的颜色定义如下：
- ⚪ 灰色（Gray）：Idle — 待机中
- 🔵 蓝色脉冲（Blue pulse）：Aware — 检测到人...
- 🟢 绿色（Green）：Auth — 就绪
- 🟣 紫色脉冲（Purple pulse）：Chat — 对话中
- 🟡 黄色（Yellow）：Degraded — 降级模式（摄像头或麦克风不可用）

脉冲动画 MUST 通过 CSS animation 实现，包含 scale 和 opacity 的周期变化。

#### Scenario: 待机状态显示灰色圆点
- **WHEN** 状态机处于 Idle 状态
- **THEN** 指示点显示为灰色（#9E9E9E），无动画

#### Scenario: 感知状态显示蓝色脉冲动画
- **WHEN** 状态机进入 Aware 状态
- **THEN** 指示点变为蓝色（#2196F3），并启动脉冲 CSS 动画（scale 从 1 到 1.3，opacity 从 1 到 0.6，周期 1.5s）

#### Scenario: 降级模式显示黄色
- **WHEN** 摄像头或麦克风不可用导致状态机进入 Degraded 状态
- **THEN** 指示点变为黄色（#FFC107），无动画

### Requirement: 功能型聊天面板（原聊天面板占位）

原聊天面板为静态占位显示个性化欢迎语（Idle 隐藏 / Auth 显示 "下午好，[name] [badge]" / Chat 显示 "[name]，我在听"）。现修改为全功能型聊天界面，包含历史消息列表、自动滚动至底部行为、以及随底层子状态（sub-state）动态响应的输入状态指示。

**消息列表布局：**
- 消息列表 SHALL 占据面板主体区域，采用弹性布局（flex column），消息项从底部向上排列
- 列表容器 SHALL 启用纵向滚动（overflow-y: auto），并在新消息到达时自动滚动至底部
- 滚动至底部 SHALL 仅在用户未主动向上翻阅历史消息时自动执行；若用户已上滚查看历史，新消息到达时不抢夺滚动位置，但 SHALL 在底部显示 "[N] 条新消息" 浮窗按钮，点击后平滑滚动至底部
- 消息列表背景 SHALL 为半透明毛玻璃效果（backdrop-filter: blur），与窗口整体风格一致

**输入状态指示区域：**
- 消息列表底部 SHALL 固定显示输入状态指示区域，反映底层状态机的当前子状态（sub-state）
- 各子状态文字提示如下：
  - Listening → "正在听..." + 波形动画
  - Transcribing → "正在转录..." + 脉冲圆点动画
  - Thinking → "正在思考..." + 旋转加载动画
  - Speaking → "正在说话..." + 音量条动画
- 当系统处于 Idle/Standby 状态时，输入状态区域 SHALL 显示 "点击或按空格开始对话"
- 该指示区域 SHALL 与子状态动画（见 ADDED: 子状态动画）视觉联动

**会话历史加载：**
- 应用启动时，SHALL 从本地存储中加载最近一次会话的消息记录
- 默认加载最近 50 条消息，并提供 "加载更早消息" 按钮（位于消息列表顶部），点击后每次追加加载 30 条
- 消息记录 SHALL 使用 SQLite 本地存储，表结构包含：消息 ID（UUID）、角色（user/assistant）、内容文本、时间戳、关联的 TTS 音频文件路径（可选）

#### Scenario: 用户新消息自动滚动至底部

- **WHEN** 用户说话完毕，转录文本生成一条新的用户消息气泡
- **THEN** 消息列表自动滚动至底部，展示最新消息

#### Scenario: 用户翻阅历史时不抢夺滚动

- **WHEN** 用户已向上滚动消息列表查看历史消息
- **AND** 新消息到达
- **THEN** 消息列表不自动滚动，底部显示 "[N] 条新消息" 浮窗按钮

#### Scenario: 启动时加载最近会话

- **WHEN** 应用启动且本地存储中存在历史会话记录
- **THEN** 消息列表加载最近 50 条消息并展示，自动滚动至底部

#### Scenario: 转录中显示输入状态

- **WHEN** 底层状态机子状态切换至 Transcribing
- **THEN** 输入状态指示区域显示 "正在转录..." 及脉冲圆点动画，输入框区域不可交互

### Requirement: 系统托盘

系统 MUST 在 Windows 系统托盘中始终显示应用图标。托盘右键菜单 SHALL 包含以下菜单项：显示/隐藏窗口（Show/Hide）、状态子菜单（显示当前状态）、设置（Phase 1 置灰禁用）、退出（Quit）。双击托盘图标 SHALL 切换窗口的显示/隐藏状态。点击窗口关闭按钮 SHALL 将应用最小化至托盘而非任务栏。

#### Scenario: 双击托盘图标切换窗口
- **WHEN** 窗口处于隐藏状态且用户双击托盘图标
- **THEN** 窗口显示并置于最前

#### Scenario: 托盘菜单显示当前状态
- **WHEN** 用户右键点击托盘图标并悬停在"Status"子菜单
- **THEN** 子菜单中显示当前状态文本（如"待机中"）

#### Scenario: 设置菜单项置灰
- **WHEN** Phase 1 中用户点击托盘菜单的"Settings"
- **THEN** 菜单项呈灰色禁用状态，无任何响应

#### Scenario: 关闭窗口最小化到托盘
- **WHEN** 用户点击窗口的关闭按钮
- **THEN** 窗口隐藏，应用继续在系统托盘运行

### Requirement: 设置面板占位

系统 MUST 提供一个设置面板的访问入口，可从系统托盘菜单或展开模式侧边栏进入。设置面板内容区域 SHALL 显示占位信息"设置功能将在后续版本中开放"。Phase 1 仅包含设置访问入口，不包含功能性设置界面。

#### Scenario: 从侧边栏打开设置面板
- **WHEN** 用户处于全模式并在侧边栏点击"设置"入口
- **THEN** 主内容区域显示占位文本"设置功能将在后续版本中开放"

#### Scenario: 从托盘菜单打开设置面板
- **WHEN** 用户右键托盘图标并点击"Settings"
- **THEN** 窗口显示（如隐藏），主内容区域显示占位文本"设置功能将在后续版本中开放"

### Requirement: 开机自启

系统 SHALL 支持配置开机自启动。在 Windows 平台上通过注册表 Run 键实现。该选项通过配置文件 `config/frank.yaml` 中的 `auto_start: true/false` 控制。默认值为 `true`（启用）。应用启动时 SHALL 读取该配置并调用 Electron 的 `app.setLoginItemSettings` 设置开机自启。

#### Scenario: 默认启用开机自启
- **WHEN** 用户安装 Frank 后首次启动
- **THEN** 应用读取 `config/frank.yaml` 中 `auto_start: true`，通过 `app.setLoginItemSettings` 注册 Windows 开机自启

#### Scenario: 配置关闭开机自启
- **WHEN** 用户在 `config/frank.yaml` 中将 `auto_start` 设置为 `false` 后重启应用
- **THEN** 应用移除注册表中的自启项，下次开机不再自动启动

### Requirement: IPC 集成

系统 MUST 实现主进程与渲染进程之间的 IPC 通信。渲染器通过 `contextBridge` 暴露的 API 监听主进程转发的状态变更事件。主进程 SHALL 接收来自 Python 后端的状态事件并转发至渲染进程。渲染器收到状态变更后 SHALL 响应式地更新 UI：状态指示点颜色、标题栏文本和面板内容。禁止使用轮询机制。

#### Scenario: 状态变更通过 IPC 传递到渲染器
- **WHEN** Python 后端发出状态变更事件（例如从 Idle 变为 Aware）
- **THEN** 主进程通过 `webContents.send` 向渲染进程发送 `state-changed` 事件，渲染器通过 `contextBridge` 监听到事件后更新指示点颜色为蓝色脉冲并更新标题栏文本为"Frank - 检测中..."

#### Scenario: 渲染器响应式更新聊天面板
- **WHEN** 主进程转发状态变更事件为 Chat
- **THEN** 渲染器更新标题栏文本为"Frank - 对话中"，指示点变为紫色脉冲，输入框占位文本变为"正在听..."

#### Scenario: 无轮询验证
- **WHEN** 状态未发生变更
- **THEN** 渲染进程不发起任何轮询请求，UI 保持不变

### Requirement: 角色徽章 UI 组件

系统 MUST 提供一个轻量级角色徽章 UI 组件（RoleBadge），用于在用户名称旁侧显示身份标识。徽章为小型彩色圆角标签，包含角色名称和可选 emoji 图标。

各角色对应的视觉风格定义如下：

| 角色 | CSS 类名 | 背景色 | 文本颜色 | 图标 |
|---|---|---|---|---|
| Owner | `role-badge--owner` | 金色渐变 (#FFD700 → #FFA500) | #5C3D00 | 👑 |
| Adult | `role-badge--adult` | 蓝色 (#2196F3) | #FFFFFF | 无 |
| Child | `role-badge--child` | 绿色 (#4CAF50) | #FFFFFF | 无 |
| Guest | `role-badge--guest` | 灰色 (#9E9E9E) | #FFFFFF | 无 |

徽章 SHALL 具有以下样式特征：
- 高度 20px，内边距水平 8px 垂直 2px
- 圆角 10px（完全药丸形状）
- 字体大小 12px，字重 500
- 图标与文字间距 4px
- 悬停时显示 tooltip 提示角色全称

Owner 角色徽章 SHALL 额外应用金色脉冲动画（golden pulse），通过 CSS `@keyframes goldenGlow` 实现 box-shadow 从 0 到 6px 的周期变化，周期 2s。

#### Scenario: Adult 角色显示蓝色徽章
- **WHEN** 当前已验证用户角色为 Adult
- **THEN** 用户名称旁渲染蓝色徽章，文本为 "Adult"，背景色 #2196F3

#### Scenario: Owner 角色显示金色徽章并带动画
- **WHEN** 当前已验证用户角色为 Owner
- **THEN** 用户名称旁渲染金色徽章，包含 👑 图标，文本为 "Owner"，并应用金色脉冲 CSS 动画

#### Scenario: 悬停徽章显示 tooltip
- **WHEN** 用户鼠标悬停在 Child 角色徽章上
- **THEN** 显示 tooltip 文本 "角色：Child（儿童模式）"

### Requirement: 成员管理面板

系统 MUST 提供一个成员管理面板，可从工具栏 "👥 成员" 按钮或展开模式的侧边栏打开。

面板布局分为三个区域：

**区域一：已识别成员列表**
- 表格/列表形式展示所有已注册的家庭成员
- 每行包含：头像占位（首字母圆形图标）、显示名称（display_name）、角色徽章、最后活跃时间（相对时间，如"2小时前"）
- 按最后活跃时间降序排列
- 每行右侧提供上下文菜单按钮（三个点），点击后显示"编辑"和"删除"选项
- 删除操作前 SHALL 弹出确认对话框

**区域二：待识别成员列表**
- 展示尚未完成完整注册流程的待识别成员
- 每行包含：顺序编号（"成员 1"、"成员 2" ...）、识别进度计数（已采集样本数/总需求数）、[识别] 操作按钮
- 点击 [识别] 按钮 SHALL 打开注册流程向导（见 ADDED: 注册流程 UI）
- 待识别成员数量无上限

**区域三：添加成员入口**
- 面板底部显示 "[添加成员]" 按钮
- 按钮样式：主色填充按钮，宽度 100%
- 点击后 SHALL 打开注册流程向导（见 ADDED: 注册流程 UI），创建一个新的待识别成员条目

#### Scenario: 打开成员管理面板
- **WHEN** 用户点击工具栏中的 "👥 成员" 按钮
- **THEN** 成员管理面板打开，已识别区域显示所有已注册成员，待识别区域显示未完成注册的条目

#### Scenario: 已识别成员按活跃度排序
- **WHEN** 成员管理面板打开且已有三名已注册成员（小张-10分钟前、小王-2小时前、小李-昨天）
- **THEN** 列表顺序为：小张、小王、小李

#### Scenario: 点击待识别成员的识别按钮
- **WHEN** 用户在待识别区域点击 "成员 2" 行上的 [识别] 按钮
- **THEN** 系统打开注册流程向导，预填充该成员条目

#### Scenario: 删除已识别成员
- **WHEN** 用户点击已识别成员行上的菜单按钮，选择"删除"
- **THEN** 弹出确认对话框，确认后该成员从列表中移除

### Requirement: 注册流程 UI

系统 MUST 提供一个多步骤注册流程向导（RegistrationWizard），用于新成员的生物特征注册。向导以 Modal 叠加层形式呈现，包含步骤指示器（Step 1/2/3/4）和前进/后退导航。

**Step 1 — 基本信息录入**
- 输入字段：名称（display_name，文本输入，必填，最大 20 字符）
- 角色选择：四个单选卡片展示（Owner、Adult、Child、Guest），每个卡片包含角色图标、名称和简短描述
- 角色描述：
  - Owner：家庭管理员，拥有全部权限
  - Adult：成年家庭成员
  - Child：儿童，启用内容过滤
  - Guest：访客，临时访问权限
- [下一步] 按钮 SHALL 在所有必填项填充后启用
- 点击 [取消] 或按 Escape 键 SHALL 关闭向导并丢弃未保存的进度

**Step 2 — 面部采集**
- 界面布局：左侧为摄像头实时预览画面（video 元素），右侧为采集状态
- 实时预览 SHALL 显示"请正视摄像头"引导文本（覆盖在预览画面中央半透明）
- 采集进度显示：圆形进度指示器 "3/5"（共需采集 5 张不同角度的面部图像）
- 每成功捕获一帧，进度计数递增，并伴有短暂的成功动画（绿色闪烁）
- 摄像头权限检查：若摄像头不可用，SHALL 显示错误提示"未检测到摄像头，请检查设备连接"
- 采集完成后自动进入下一步

**Step 3 — 语音采集**
- 界面显示引导文本 "请朗读以下句子："
- 句子展示区域：显示一句随机中文短句（从预置列表中选取），字体 18px，加粗
- 录音控制按钮：圆形麦克风按钮，点击开始录制，录制中按钮呈脉冲红色动画
- 进度显示："已录制 1/3"
- 每完成一次录制，进度递增并更换句子
- 录制完成后自动进入下一步
- 麦克风权限检查：若麦克风不可用，SHALL 显示错误提示"未检测到麦克风，请检查设备连接"

**Step 4 — 验证与确认**
- 显示注册摘要信息：
  - 姓名：[display_name]
  - 角色：[role_name] [role_badge]
  - 面部样本：5/5 ✓
  - 语音样本：3/3 ✓
- [确认] 按钮：点击后完成注册，关闭向导，新成员出现在已识别成员列表中
- [上一步] 按钮：允许返回修改任意步骤
- 确认后 SHALL 触发 `member-registered` 事件，更新全局身份状态

#### Scenario: 完整注册流程
- **WHEN** 用户点击 [添加成员] 按钮，填写名称为"小明"，选择 Child 角色，点击下一步
- **AND** 完成面部采集 5/5
- **AND** 完成语音采集 3/3
- **AND** 在 Step 4 点击 [确认]
- **THEN** 向导关闭，"小明" 出现在已识别成员列表中，并带有 Child 绿色徽章

#### Scenario: Step 2 摄像头不可用
- **WHEN** 注册流程进入 Step 2 但系统未检测到摄像头

**用户消息气泡（User Bubble）：**
- 右对齐显示，背景色为蓝色渐变（#2196F3 → #1976D2）

- 气泡下方不显示任何操作按钮

**助手消息气泡（Assistant Bubble）：**
- 左对齐显示，背景色为灰色（#2D2D2D）或深色主题色
- 文本颜色浅色（#E0E0E0），字号 14px，行高 1.6
- 气泡形状：左上角直角、其余三角圆角（tail 朝左），圆角半径 12px
- 气泡内边距：上下 12px、左右 16px
- 气泡最大宽度为面板宽度的 85%（比用户气泡略宽，容纳更长文本）
- 气泡上方 SHALL 显示 "Frank" 标签和发布时间戳
- 气泡底部 SHALL 包含 TTS 播放控制按钮组（见 ADDED: TTS 控制）
- 当助手消息为流式输出（streaming）时，气泡 SHALL 显示打字机效果，逐字展现文本

**空状态：**
- 当消息列表为空且无历史会话时，SHALL 显示空状态引导文案 "开始对话吧 — 点击麦克风或按空格键说话"

**消息分组：**
- 同一角色连续多条消息 SHALL 合并显示，仅首条消息显示头像/标签和时间戳，后续连续消息气泡间间距缩小至 4px
- 用户与助手交替时，气泡间距为 12px

#### Scenario: 空消息列表显示引导文案

- **THEN** 消息列表中央显示 "开始对话吧 — 点击麦克风或按空格键说话"

### Requirement: 任务看板面板

系统 MUST 提供一个任务看板面板（TaskDashboard），用于展示当前用户相关的所有任务及其执行状态。面板可从展开模式侧边栏 "📋 任务" 导航项或紧凑模式标题栏 "📋" 按钮进入。

**面板布局与内容：**

**区域一：任务列表**
- 以垂直列表形式展示所有任务，每条任务项包含：
  - 任务标题（如 "分析项目结构"）
  - 任务唯一 ID（UUID 缩写，灰色 11px，如 "#a3f8b"）
  - 创建时间（相对时间，如 "3分钟前"）
  - 所属会话/上下文标签（如 "对话 #2"），可选
  - 进度条（水平 progress bar）：0-100%，根据任务当前完成度实时更新，高度 6px，圆角 3px，背景色 #333
    - 已知总步骤的任务显示百分比文本（如 "3/5"）及对应填充宽度
    - 未知总步骤的任务使用不确定进度动画（条纹滚动）
  - 状态徽章：
    - 进行中（In Progress）：蓝色徽章 #2196F3
    - 已完成（Completed）：绿色徽章 #4CAF50
    - 失败（Failed）：红色徽章 #F44336
    - 已取消（Cancelled）：灰色徽章 #9E9E9E
  - 经过时间（elapsed time），格式 "MM:SS" 或 "HH:MM:SS"

**区域二：操作按钮组**
- 每条任务项底部 SHALL 包含以下操作按钮（根据状态启用/禁用）：
  - [查看结果]（View Result）：仅在 Completed 状态下启用。点击后以弹窗展示任务结果摘要
  - [重试]（Retry）：仅在 Failed 状态下启用。点击后重新提交任务，创建同名新任务
  - [忽略/关闭]（Dismiss）：在 Completed 和 Failed 状态下均启用。点击后任务从列表中隐藏（软删除），提供 "显示已关闭的任务" 切换开关
  - [取消]（Cancel）：仅在 In Progress 状态下启用。点击后停止任务，状态变更为 Cancelled

**区域三：筛选与排序**
- 面板顶部 SHALL 提供筛选工具栏：
  - 状态筛选下拉框：全部 / 进行中 / 已完成 / 失败，默认 "全部"
  - 时间排序：创建时间降序（默认）/ 升序
  - 搜索框：按任务标题关键词模糊搜索
- 筛选结果为空时显示空状态文案 "暂无匹配的任务"

**区域四：统计摘要**
- 面板顶部（筛选栏上方）SHALL 显示小型统计卡片行，包含：总任务数、进行中、已完成、失败

**实时更新：**
- 任务看板 SHALL 通过 IPC 监听 `task-status-changed` 事件，实时更新对应任务项的进度和状态
- 当任务状态变更时，对应行 SHALL 短暂高亮 500ms 以吸引注意

**数据持久化（SQLite 表 `tasks`）：**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT UUID PK | 任务唯一标识 |
| title | TEXT | 任务标题 |
| status | TEXT | in_progress / completed / failed / cancelled / dismissed |
| progress | INTEGER | 0-100 |
| user_id | TEXT | 关联用户 UUID，用于多人模式过滤 |
| conversation_id | TEXT | 关联会话 UUID，可为 NULL |
| created_at | INTEGER | Unix 时间戳 |
| updated_at | INTEGER | Unix 时间戳 |
| result_summary | TEXT | 任务结果摘要，可为 NULL |
| error_message | TEXT | 失败原因描述，可为 NULL |

**用户过滤：**
- 多人模式下，任务看板默认显示当前已识别用户的任务
- 看板顶部 SHALL 提供用户筛选下拉框，可切换查看 "我的任务"、"所有人的任务" 或指定用户
- 筛选切换通过 IPC `filter-tasks-by-user` 消息实时刷新

#### Scenario: 打开任务看板查看任务列表

- **WHEN** 用户点击侧边栏 "📋 任务" 导航项或紧凑模式标题栏 "📋" 按钮
- **THEN** 任务看板面板打开，展示当前用户的所有任务列表，按创建时间降序排列，统计卡片显示各项计数

### Requirement: 多人模式指示器

系统 MUST 在标题栏状态指示点右侧新增一个多人模式指示器（MultiPersonIndicator），当系统检测到多人同时存在于摄像头视野中时，提示当前处于多人交互模式。

**指示器视觉规范：**
- 非多人模式（单人模式）：指示器隐藏，不占用标题栏空间
- 多人模式：显示一个红色实心圆点（#F44336），直径 8px，位于状态指示器右侧 6px 处
- 红色圆点 SHALL 带有缓慢脉冲动画（CSS animation：opacity 0.6 → 1.0，周期 2s，ease-in-out）
- 悬停红色圆点时 SHALL 显示 tooltip "多人模式已开启"

**排队人数标签：**
- 当多人模式激活且有多人正在排队等待交互时，红色圆点右侧 SHALL 显示排队人数标签
- 标签样式：白色文本，红色背景圆角标签（背景色 #F44336，高度 18px，内边距水平 6px，圆角 9px，字号 11px，字重 600）
- 标签文本格式："+N"，其中 N 为当前排队人数（如 "+3" 表示 3 人在排队）
- 当排队人数为 0 时标签隐藏，仅显示红色圆点
- 排队人数上限显示为 "+99"，超过 99 人时仍显示 "+99"

**排队队列详情弹出层（Popover）：**
- 点击红色圆点或排队人数标签 SHALL 打开小型弹出层，展示排队等候人员列表
- 弹出层位置：标题栏下方，左对齐于指示器位置
- 弹出层样式：深色背景 #1E1E1E，圆角 8px，阴影 0 4px 12px rgba(0,0,0,0.3)，内边距 12px
- 弹出层宽度 240px，最大高度 300px（超出滚动）
- 列表每一项包含：
  - 头像占位（首字母圆形图标，直径 32px，随机柔和背景色）
  - 显示名称（display_name）
  - 等待时间（相对时间，如 "等待 45秒"）
  - 当前正在交互的用户显示 "对话中" 绿色徽章
- 列表按加入排队时间升序排列（FIFO），当前交互用户始终置顶
- 外部点击或按 Escape 键 SHALL 关闭弹出层

**状态切换逻辑：**
- 多人与单人模式的切换由后端人脸检测模块驱动
- 检测到 >1 张人脸 → 后端发出 `multi-person-detected` → 主进程转发 → 渲染进程显示红色圆点
- 检测到 ≤1 张人脸 → 后端发出 `single-person-detected` → 渲染进程隐藏红色圆点并收起队列

**IPC 事件：**
- 主进程 → 渲染进程：`multi-person-status-changed`
- 负载格式：
  ```json
  {
    "enabled": true,
    "queue": [
      {"user_id": "uuid-1", "display_name": "小王", "waiting_since": 1717000000, "is_active": true},
      {"user_id": "uuid-2", "display_name": "小李", "waiting_since": 1717000030, "is_active": false}
    ]
  }
  ```

#### Scenario: 非多人模式指示器隐藏

- **WHEN** 系统处于单人模式，`multi-person-status-changed` 事件 payload 中 `enabled: false`
- **THEN** 标题栏不显示红色圆点，不占用任何空间

#### Scenario: 多人模式显示红色圆点

- **WHEN** 系统进入多人模式（检测到 2 张人脸），事件 payload 中 `enabled: true`, `queue: []`
- **THEN** 标题栏状态指示器右侧显示红色脉冲圆点，排队人数标签隐藏

#### Scenario: 排队人数标签更新

- **WHEN** 排队队列中有 3 人等待
- **THEN** 红色圆点右侧显示 "+3" 红色标签
- **WHEN** 排队人数变为 0
- **THEN** "+3" 标签隐藏

#### Scenario: 打开排队详情弹出层

- **WHEN** 用户点击红色圆点
- **THEN** 弹出层显示排队人员列表，当前交互用户显示 "对话中" 绿色徽章，其他用户显示等待时间

#### Scenario: Escape 关闭弹出层

- **WHEN** 排队详情弹出层已打开，用户按 Escape 键
- **THEN** 弹出层关闭

#### Scenario: 恢复到单人模式隐藏所有指示

- **WHEN** 多人模式中除一人外所有人离开摄像头视野
- **THEN** 红色圆点隐藏，排队标签隐藏，弹出层（如打开）关闭，界面恢复单人模式状态

#### Scenario: 排队人数上限显示

- **WHEN** 排队人数达到或超过 100 人
- **THEN** 标签文本显示 "+99" 而非实际数字

### Requirement: 技能管理面板

系统 MUST 提供一个技能管理面板（SkillManagementPanel），用于查看和管理系统中所有已安装的技能（Skill）。面板可从展开模式侧边栏 "🧩 技能" 导航项或紧凑模式标题栏 "🧩" 按钮进入。

**面板布局与内容：**

**区域一：已安装技能列表**
- 以卡片网格（Card Grid）展示所有已安装技能，每张技能卡片包含：
  - 技能图标（默认取技能名称首字符作为图标占位）
  - 技能名称（如 "代码审查"）
  - 技能唯一标识符 slug（灰色 11px，如 "code-review"）
  - 简短描述（一行文本，超出省略）
  - **关键词标签**（Keywords）：以小型圆角标签展示，高度 22px，内边距水平 8px，圆角 4px，背景色半透明 rgba(255,255,255,0.1)，文字色 #E0E0E0，字号 12px，标签间距 6px。最多显示 3 个，超出部分以 "+N" 显示
  - **权限需求标签**（Permissions）：以小型圆角标签展示权限名称，如 "读写文件"、"网络访问"、"执行命令"
  - **启用/禁用开关**（Toggle Switch）：
    - 启用状态：开关蓝色 #2196F3，技能可被触发
    - 禁用状态：开关灰色 #757575，技能不可被触发
  - 状态徽章：
    - 已启用：绿色标签
    - 已禁用：灰色标签
    - 系统内置：蓝色标签 "系统内置"，开关禁用（不可操作），悬停 tooltip "系统内置技能不可禁用"
  - 最后使用时间（相对时间，如 "昨天"、"3天前"），未使用显示 "从未使用"

**区域二：技能详情浮窗**
- 点击技能卡片任意区域（除开关外）SHALL 从右侧滑入详情浮窗（Slideover，宽度 400px），包含：
  - 技能名称与图标（顶部区域）
  - 完整描述（多行文本，无省略）
  - 完整关键词列表（不截断）
  - 完整权限需求列表
  - **触发示例**（trigger examples）：展示用户可以说哪些话触发该技能，如 "审查这段代码"
  - **使用统计**：
    - 总调用次数
    - 今日调用次数
    - 成功率（百分比）
  - 版本号（如 "1.2.0"）
  - 作者信息（如 "Frank Team"）
  - **状态历史**：最近 5 条启用/禁用变更记录，包含操作时间和操作人
  - [卸载技能] 按钮（红色文字），点击后弹出确认对话框 "确定要卸载 [技能名称] 吗？此操作不可撤销"
- 点击关闭按钮或外部区域 SHALL 关闭浮窗

**区域三：搜索与筛选**
- 面板顶部 SHALL 提供搜索框，按技能名称或关键词模糊搜索
- 筛选下拉框：全部 / 已启用 / 已禁用，默认 "全部"

**区域四：空状态**
- 无已安装技能时显示 "暂无已安装的技能" 及引导文本 "请通过技能市场或命令行安装技能"

**数据来源与 IPC 集成：**
- 技能列表通过 IPC `get-skills` 从主进程获取，主进程维护全局技能注册表
- 启用/禁用状态变更通过 IPC `toggle-skill` 发送至主进程，主进程更新后端配置并返回操作结果
- 技能状态变更后，主进程通过 `skills-updated` 推送新状态至所有渲染进程
- 切换时开关显示短暂加载状态（置灰，指针事件禁用）；操作失败时恢复原状态并显示 Toast 错误提示 "技能状态更新失败"
- 技能启用/禁用状态 SHALL 持久化存储在后端配置中

#### Scenario: 打开技能管理面板

- **WHEN** 用户点击侧边栏 "🧩 技能" 导航项或紧凑模式标题栏 "🧩" 按钮
- **THEN** 技能管理面板以卡片网格展示所有已安装技能，每张卡片包含名称、描述、关键词标签和启用开关

#### Scenario: 切换技能启用/禁用状态

- **WHEN** 用户点击某已启用技能卡片上的开关
- **THEN** 开关短暂显示加载状态，成功后切换至关闭位置，卡片状态徽章变为 "已禁用"
- **AND** 该技能的触发关键词在系统中不再响应

#### Scenario: 系统内置技能开关不可操作

- **WHEN** 用户悬停系统内置技能的开关
- **THEN** 显示 tooltip "系统内置技能不可禁用"，开关保持启用状态且不可点击

#### Scenario: 查看技能详情

- **WHEN** 用户点击某技能卡片（非开关区域）
- **THEN** 从右侧滑入 400px 宽的详情浮窗，展示完整描述、触发示例、使用统计、版本号和状态历史

#### Scenario: 按关键词搜索技能

- **WHEN** 用户在搜索框输入 "翻译"
- **THEN** 技能卡片列表实时过滤，仅显示名称或关键词中包含 "翻译" 的技能

#### Scenario: 卸载技能确认

- **WHEN** 用户在技能详情中点击 [卸载技能] 按钮
- **THEN** 弹出确认对话框 "确定要卸载 [技能名称] 吗？此操作不可撤销"
- **AND** 用户确认后，技能被卸载，卡片从列表中移除，面板重新渲染

## ADDED Requirements (Phase 5)

### Requirement: 手势识别浮层提示
Electron 渲染器 SHALL 监听 `gesture.detected` 事件，在窗口右下角显示半透明浮层提示，内容为手势图标和中文名称，3 秒后自动淡出。

#### Scenario: 举手浮层提示
- **WHEN** 渲染器收到 `gesture.detected` 事件，`gesture_type` 为 `"raise_hand"`
- **THEN** 窗口右下角显示浮层 "✋ 举手 — 对话已暂停"，3 秒后 opacity 动画淡出至消失

#### Scenario: 挥手浮层提示
- **WHEN** 渲染器收到 `gesture.detected` 事件，`gesture_type` 为 `"wave"`
- **THEN** 窗口右下角显示浮层 "👋 挥手 — 技能已切换"

#### Scenario: 走近浮层提示
- **WHEN** 渲染器收到 `gesture.detected` 事件，`gesture_type` 为 `"come_closer"`
- **THEN** 窗口右下角显示浮层 "🚶 正在激活..."

#### Scenario: 自定义手势浮层提示
- **WHEN** 渲染器收到 `gesture.detected` 事件，`gesture_type` 为 `"custom"`，包含 `gesture_id`
- **THEN** 窗口右下角显示浮层 "🤌 [自定义手势名称]"

### Requirement: 手势暂停横幅
当 `raise_hand` 手势触发对话暂停时，聊天面板顶部 SHALL 显示暂停状态横幅。

#### Scenario: 显示暂停横幅
- **WHEN** 渲染器收到对话暂停事件
- **THEN** 聊天面板顶部显示黄色横幅："⏸️ 对话已暂停 — 再次举手即可恢复"，并显示暂停时长计时器

#### Scenario: 恢复时隐藏横幅
- **WHEN** 再次收到 `raise_hand` 手势事件（恢复对话）
- **THEN** 暂停横幅消失，聊天面板恢复正常

### Requirement: IPC 手势事件通路
Electron 主进程 SHALL 转发 Python 后端的 `gesture.detected` WebSocket 消息到渲染进程。

#### Scenario: 手势事件 IPC 转发
- **WHEN** 主进程收到 WebSocket 消息 `{ type: "gesture.detected", payload: { gesture_type: "raise_hand", confidence: 0.85 } }`
- **THEN** 主进程通过 `mainWindow.webContents.send('gesture:detected', payload)` 转发到渲染器

#### Scenario: 预加载 API 暴露手势事件
- **WHEN** 渲染器通过 `window.frankAPI` 监听事件
- **THEN** `onGestureDetected` 回调在被调用时传入 `{ gesture_type, confidence, gesture_id, timestamp }`
